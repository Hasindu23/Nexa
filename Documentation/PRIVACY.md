# Permissions, entitlements and privacy

Nexa has no analytics, crash-upload service, registration or license server. No data is collected by the app author. Local-only mode is enabled on first launch and blocks the application's AI, weather, remote artwork and update requests. Explicitly opening a web link or using a macOS share destination is a separate user action and may involve the selected application/service.

## Optional permissions

| Capability | Request trigger | Data/use |
| --- | --- | --- |
| Camera | Click Mirror | Live mirrored video only; stops when hidden; no microphone or recording |
| Music / Spotify Automation | Explicit source selection or fallback when system media is unavailable | Track metadata and playback commands |
| Calendar full access | Connect Calendar | Read upcoming events; Nexa does not create calendar events |
| Calendar Automation | Click an event | Show the selected event in Calendar |
| Reminders full access | Connect Reminders | List, create and mark tasks complete on request |
| Bluetooth | Enable Bluetooth module | Paired device names/connection state |
| Accessibility | User enables it in macOS settings, if desired | Optional synthetic Control-Command-Q for lock screen |
| Login item | Enable Launch at Login | Native SMAppService registration |

Clipboard reading has no standalone permission dialog on the targeted macOS versions. Nexa therefore supplies its own explicit opt-in explanation/toggle. Standard concealed, transient and autogenerated clipboard markers are skipped. This is not a comprehensive secret detector: pause capture before copying sensitive information. History is local JSON, not a separately encrypted database; OS account protection and FileVault are recommended for sensitive Macs. Clearing Nexa history does not erase the current system clipboard or OS backups.

The notch companion requires no Screen Recording, Full Disk Access or live location permission. Screenshot opens Apple's own capture interface and does not capture the screen inside Nexa. Storage Cleaner respects macOS file permissions; its verified Trash/Undo workflow may require Full Disk Access to inspect Trash. Nexa never grants itself that permission. Denied operations preserve the original file and report the error.

## Entitlements

`Nexa/Resources/Nexa.entitlements` contains `com.apple.security.device.camera` and `com.apple.security.automation.apple-events` for the hardened-runtime distribution configuration. Purpose strings for Camera, Calendar, Reminders, Bluetooth and Automation are in Info.plist.

This developer build is **not App Sandbox enabled**. It uses user-selected file references and Apple Events, and needs no sandbox file/network entitlements in this configuration. Do not add `com.apple.security.app-sandbox` without implementing and auditing security-scoped file access, the appropriate EventKit/Bluetooth/network permissions and Apple Events exceptions. App Store eligibility is not established.

Keychain uses `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`. No API key is placed in UserDefaults, source, logs or exported deliverables. There is no shared Keychain access group. The supplied development binary is ad-hoc signed; use stable Developer ID signing for distribution and predictable permission/Keychain identity across updates.

## Network destinations after opt-in

- **OpenAI**: the selected editor text and action/model, after pressing Send; API key as an HTTPS authorization header. Requests use `store: false`. This does not override OpenAI's own retention/account policies. Responses remain in memory until Clear or quit.
- **Open-Meteo or your configured compatible provider**: manually entered coordinates and weather fields on refresh. No live location lookup.
- **Artwork host**: Spotify-provided HTTPS artwork URL when network access is allowed and Now Playing is connected.
- **Update-feed host**: user-configured HTTPS URL after Check for updates.

No automatic selection or clipboard content upload exists. “Paste clipboard” in Assistant only fills the reviewable editor. macOS sharing services decide their own destinations; Nexa never sends Mail/Messages automatically.

## Remove data

Use Privacy → Clear clipboard database / Clear file shelf and Assistant → Remove saved key. Delete the app to stop running it. Optional local cleanup after quitting consists of the Nexa Application Support folder and the `app.nexa.mac` preferences domain; neither contains original shelf files. Login items can be removed in System Settings → General → Login Items.

## New local services in 0.2.0

System-wide Now Playing starts only after media is connected. A bundled helper reads the metadata macOS makes available and communicates through a private process pipe, with no network listener or audio capture. It stops when media is disconnected, paused or Nexa quits. Artwork supplied by macOS can display in Local-only mode without Nexa fetching a URL.

Notes, to-dos and favorite shortcut names are stored in private local JSON files. Notes are saved after a short typing debounce and on leaving the editor or quitting. Shortcuts run only after a click, and may themselves communicate with services or perform actions according to their own contents. Nexa does not automatically execute any shortcut. Mirror never autostarts on launch or after permission is granted while the panel has already closed.

## Storage Cleaner

Scans and cleanup history stay on the Mac. History contains dates, categories, sizes, results and file paths, never file contents. A private recovery area may temporarily hold the original file during a confirmed cleanup; interrupted files are preserved there for recovery. Do not remove that area before restoring any interrupted operation.

Downloads, extra folders, local Docker and Ollama are opt-in. Docker requests use only the local Docker Desktop Unix socket; Ollama requests use only localhost. There is no remote cleanup transport in this build. Scheduled scans never delete files. Every cleanup requires an exact-item review and confirmation; irreversible actions require an additional typed confirmation. See the [Storage Cleaner guide](STORAGE-CLEANER.md) for scope and recovery details.

Disk Space Explorer starts only after you choose an analysis action. It inspects accessible file and directory metadata, including hidden folders, without reading file contents. The inventory stays in memory and is not uploaded or written to cleanup history. Credential-store directories are skipped; symlinks and nested volumes are not followed. The separately requested snapshot check reads local APFS metadata and never deletes snapshots. See the [Disk Space Explorer guide](DISK-EXPLORER.md) for measurement limits and cleanup boundaries.
